# 计划 9：统一资产发现闭环与 IP/证书关联

> 当前状态：[已归档]
>
> 归档口径：代码实现、Review 和本地回归已完成；FOFA/Hunter 配额、真实 DNS/CDN/WAF 数据和授权目标验收仍由部署环境执行，不代表生产发布门禁已通过。
>
> 本计划基于 IP/IP 段大规模扫描测试结果制定，目标是把域名、IP、端口、证书和网络空间测绘结果统一为一个有界、可解释、可去重的资产发现闭环。目录扫描、WIH、站点识别、Nuclei、Afrog 和 NPoC 作为下游消费者继续保留。

## 1. 目标与结论

整体思路正确，但证书中的 CN/SAN 不能无条件直接作为主动扫描目标。证书应分成两层处理：

- 证书本身全部采集并保存；
- 证书域名只有在通过范围、DNS 和 CDN/WAF 校验后，才进入主动扫描与后续反查。

统一闭环如下：

```text
域名、IP、端口、证书、测绘引擎、域名爆破
        ↕
统一候选资产与证据关系
        ↓
Web、目录扫描、WIH、Nuclei、Afrog、NPoC
```

## 2. 实施前的当前缺口

以下内容是本计划实施前记录的缺口，完成状态见第 12 节。

现有代码已经具备部分能力，但还没有统一接通：

- 域名任务已经支持 IP 反查和证书反查；
- IP 任务可以采集 SSL 证书，但没有把证书域名和 FOFA/Hunter 结果接入域名资产链路；
- IP 反查结果虽然包含 `pivot_ip`，域名任务后续按来源合并时会丢失该字段；
- 现有 IP 反查后的 DNS 构建只判断“域名能否解析”，没有判断“是否解析回产生该候选的扫描 IP”；
- 新建任务没有 NPoC 选择项，NPoC 配置目前主要存在于策略任务；
- NPoC 启动同步只有在数据库集合为空时才自动执行，可能导致已有旧数据时新插件不出现。

`dns_query_plugin` 表示 FOFA、Hunter、Shodan 等网络空间测绘引擎；`search_engines` 表示百度、必应等页面搜索，两者不能混淆，但结果都应进入统一候选去重和校验流程。

## 3. 两类任务的闭环

| 任务类型 | 资产扩展路径 |
|---|---|
| 域名目标 | 域名爆破、测绘引擎查询、历史资产查询 → DNS/IP → 端口与 Web → 证书 → 证书/IP 反查 → 校验后的新域名 → 继续爆破和扫描 |
| IP/IP 段目标 | IP/端口扫描 → Web 服务识别 → 默认证书和 SNI 证书 → IP 反查域名 → DNS 必须解析回目标 IP → 对确认域名的主域爆破 → Web/证书/测绘引擎继续扩展 |

顺序不作为业务契约。实现应以候选队列和证据关系驱动，允许不同来源在任务内按阶段预算调度。

### 3.1 域名任务

1. 保留现有域名爆破、测绘引擎、历史资产和页面搜索能力。
2. 对已解析的公网 IP 执行 FOFA/Hunter 等 IP 反查。
3. 对开放 Web 端口采集默认证书，并在有域名上下文时执行受限 SNI 证书采集。
4. 对非 CDN/WAF 端点的证书按证书身份执行测绘引擎反查。
5. 对所有 IP/证书反查域名重新执行 DNS 校验。
6. 通过校验且属于原始主域范围的域名进入域名资产、Web 目标和下一轮候选队列。

### 3.2 IP/IP 段任务

1. 保留 IP 段端口扫描、服务识别、Web 站点识别和证书采集。
2. 对扫描目标 IP 和后续确认的 IP 执行 IP 反查。
3. 对 IP 反查返回的每个域名重新解析，只有 A/AAAA 结果包含原始扫描 IP 才进入主动扫描。
4. 对确认域名提取主域，执行受控域名爆破。
5. 爆破得到的域名仍必须解析回原扫描 IP，不能只因为属于同一个主域就放行。
6. 将确认域名绑定到已有 IP:Port，生成带 Host 的 HTTP/HTTPS Web 目标。
7. 使用确认域名作为 SNI 重新采集证书，再按证书身份执行测绘引擎反查。
8. 新发现资产继续进入有界收敛循环。

## 4. 资产准入规则

### 4.1 通用规则

候选资产必须经过以下步骤：

1. 标准化域名、IP、端口和证书身份；
2. 过滤泛域名、公共后缀和非法域名；
3. 执行任务范围校验；
4. 执行 DNS A/AAAA 解析；
5. 对比 DNS IP 与来源 `pivot_ip` 或来源证书端点 IP；
6. 判断来源 IP 是否为 CDN/WAF；
7. 写入候选关系和最终决策。

### 4.2 域名任务规则

- 反查结果必须属于原始主域及其子域；
- 反查域名必须解析到产生该候选的 IP；
- 证书域名必须解析到证书来源端点 IP；
- CDN/WAF 端点的证书仍然保存，但不触发证书反查和主动扩展；
- DNS 暂时失败记录为 `degraded/pending`，不能静默当作无资产；
- 解析到其它 IP 的域名保留证据，但不进入主动扫描。

### 4.3 IP 任务规则

- 测绘引擎返回的域名必须重新解析；
- 只有 DNS A/AAAA 包含本次扫描目标 IP，才进入主动扫描；
- 不解析回目标 IP 的域名只保留证据；
- 证书 CN/SAN 域名遵循同样的 IP 绑定规则；
- 证书来源为 CDN/WAF 时，证书入库，但跳过主动扩展；
- 证书域名不解析回来源 IP 时，仅作为历史/关联证据保存。

## 5. 统一资产发现服务

新增任务级 `UnifiedAssetDiscoveryStageService`，复用现有 TaskPipeline、DNS 策略、证书采集、测绘 provider、结果写入和任务收尾机制。

候选类型固定为：

- `domain`
- `ip`
- `endpoint`
- `certificate`

每条关系至少保留：

- 来源：IP 反查、证书 CN、证书 SAN、证书反查、域名爆破、历史资产、页面搜索；
- `pivot_ip`、`pivot_endpoint`、`pivot_cert_key`；
- DNS 当前解析 IP；
- CDN/WAF 判断结果；
- 范围判断结果；
- 最终状态：`accepted`、`evidence_only`、`rejected`、`degraded`；
- 排除原因和时间。

必须修复当前 IP 反查流程中 `pivot_ip` 被丢弃的问题，不能只按 provider 和域名合并结果。

建议新增任务级 `asset_pivot_evidence` 集合，用于保存候选关系、DNS 结果和排除原因。正式资产继续写入现有 `domain`、`ip`、`cert` 和 `site` 集合，证据集合不替代正式资产集合。

证据集合建议使用以下自然键幂等写入：

```text
task_id + relation_type + source + candidate + pivot_ip
```

不得保存 provider 原始响应中的 API Key、Token、Cookie 或无关请求头。

## 6. 有界收敛与预算

默认启用统一闭环，但必须受预算保护：

- 最大收敛轮次：3；
- IP 反查 IP 数量：复用 `IP_PIVOT_QUERY_MAX_IPS`；
- 证书反查证书数量：复用 `CERT_PIVOT_QUERY_MAX_CERTS`；
- 反查新增域名数量：复用现有 `*_MAX_DOMAINS`；
- IP 任务最多展开的主域数量：20；
- 增加统一资产闭环阶段超时；
- 候选按规范化 key 去重；
- 同一任务内同一 IP、证书、域名和端点不得重复调用 provider、DNS、证书或端口扫描；
- 达到预算后保留未处理候选，并记录 `budget_exhausted`。

建议增加以下配置，默认值按本计划确定：

```text
ASSET_DISCOVERY_ENABLE=true
ASSET_DISCOVERY_MAX_ROUNDS=3
ASSET_DISCOVERY_MAX_DOMAIN_ROOTS=20
ASSET_DISCOVERY_MAX_DOMAINS=200
ASSET_DISCOVERY_REQUIRE_IP_MATCH=true
ASSET_DISCOVERY_DOMAIN_BRUTE_ENABLE=true
ASSET_DISCOVERY_STAGE_TIMEOUT_SEC=1800
```

收敛结束后，进入或继续执行站点识别、目录扫描、WIH、Nuclei、Afrog 和 NPoC。WIH 运行期间产生的新主机继续使用已有动态发现和收尾机制。

## 7. 新建任务 NPoC 配置

普通新建任务增加：

- `npoc_service_detection`；
- `poc_config`。

数据结构沿用策略配置：

```json
{
  "poc_config": [
    {"plugin_name": "plugin_name", "enable": true}
  ]
}
```

UI 要求：

- 新建任务加载 `/poc/` 插件列表；
- 按 `plugin_type=poc` 展示 NPoC；
- 提供“全选/清空”；
- 支持单个插件勾选；
- 未选择时不执行 NPoC；
- 服务端校验插件名称，不能信任客户端任意传入的插件名；
- `npoc_service_detection` 与 NPoC 风险扫描保持独立；
- Nuclei 和 Afrog 保持工具级总开关，不增加单模板选择。

NPoC 同步改为幂等同步：

- 启动同步不能只判断数据库集合是否为空；
- 新插件应能补入已有数据库；
- 已移除插件应能清理；
- 保留手动 `/poc/sync/`；
- 同步失败必须记录明确错误，不能显示为空列表。

## 8. 日志、指标与可观测性

统一资产阶段至少记录：

- 候选 IP、域名、证书和端点数量；
- provider 原始结果数、去重数和失败数；
- DNS 匹配、无 A/AAAA、解析漂移、不匹配数量；
- CDN/WAF 跳过数量；
- `accepted`、`evidence_only`、`rejected`、`degraded` 数量；
- 每轮新增资产数量；
- 预算耗尽、阶段超时和 provider 错误；
- 证书采集数量和可参与证书反查数量；
- 下游实际收到的 Web、Nuclei、Afrog、NPoC 目标数量。

日志仅输出脱敏后的域名摘要、数量、来源和错误类型，不输出 Token、Cookie、API Key、完整证书原文或完整请求头。

## 10. 测试与验收

### 单元测试

- IP 反查域名解析回目标 IP，状态为 `accepted`；
- 反查域名解析到其它 IP，状态为 `evidence_only`；
- 多 A/AAAA 记录只要存在目标 IP 即通过；
- CNAME 最终解析到目标 IP；
- 泛域名、公共后缀和非法域名被过滤；
- CDN/WAF 证书保存但不触发主动扩展；
- provider 结果保留 `pivot_ip`、`pivot_endpoint` 和 `pivot_cert_key`；
- DNS 异常进入 `degraded/pending`，不静默转为空结果；
- 证据写入自然键幂等，不产生重复记录。

### 编排测试

- IP 任务能把确认域名转换为带 Host 的 Web 目标；
- IP 任务能对确认域名执行主域爆破；
- 爆破结果再次执行 IP 绑定校验；
- 证书 CN/SAN → DNS 校验 → SNI 证书 → 证书反查链路可重复执行；
- 多轮闭环不重复调用，达到最大轮次后停止；
- provider 超时、DNS 失败、证书失败时任务继续执行其它安全阶段并记录 degraded。

### UI/API 测试

- 新建任务出现 NPoC 配置区域；
- NPoC 列表加载成功、为空和失败时均有明确界面状态；
- 全选、清空和单插件选择正确写入 `poc_config`；
- 服务端拒绝不存在的插件名；
- Nuclei/Afrog 仍保持总开关行为。

### 代表性验收场景

1. 域名任务发现同主域新域名，并确认其解析回对应 IP。
2. IP 任务从端口证书发现域名，再经过 DNS 校验、爆破和证书反查形成二跳资产。
3. IP 段任务包含多个 IP、共享证书和 CDN IP，验证不会产生大量错误域名。
4. 日志能够解释每个候选为什么进入主动扫描、仅保留证据或被拒绝。
5. 确认域名能够进入目录扫描、WIH、Nuclei、Afrog 和 NPoC 下游目标集合。

## 11. 已确认决策

- 域名任务严格限制在原始主域范围内；
- IP 任务以“域名解析回扫描目标 IP”作为主动扫描准入条件；
- 确认后的 IP 域名允许继续执行主域爆破；
- 证书域名不解析回来源 IP 时，仅保留证据；
- 采用有界收敛，最大默认轮次为 3；
- 闭环默认开启，但受轮次、数量和时间预算限制；
- NPoC 支持全选和单选；Nuclei/Afrog 只保留总开关；
- 目录扫描、WIH、Web 指纹和漏洞扫描属于闭环下游消费者，不替代现有能力；
- 不执行远程推送，不在计划落地过程中写入敏感配置。

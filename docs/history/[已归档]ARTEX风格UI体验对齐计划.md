# ARTEX 风格 UI 体验对齐计划

状态：**已归档**。全局框架、仪表盘与任务体验、URL 路由、列表拆分和模块推广均已完成；真实浏览器多视口、主题对比度及双架构静态服务验收通过。

## 目标与基线

借鉴 ARTEX 的浅色中性视觉、清楚的信息层级和按场景组织页面的方式，改进 ARL 前端体验，同时保留 ARL 品牌、扫描能力、任务状态语义、API 与五种可选主题。砂岩白继续作为默认主题。

既有对照和仓库检查显示：

- ARTEX 的视觉层级和页面完成度更稳定；ARL 的主题、控件基础和扫描专用数据更完整。本次重点是 UI 编排、导航可达性和页面结构，不改变后端技术栈或扫描流程。
- ARL 已使用 React、TypeScript、Vite、TanStack Query、Tailwind CSS 与 DaisyUI，已有 `PageHeader`、语义颜色 token、主题切换、懒加载及通用 `DataTable`。
- 当前主视图由 `activeModuleId` 与 localStorage 驱动，没有 URL 路由；`TableModuleView` 集中处理多类模块，约 6,000 行。
- 仪表盘已有队列 ready/reserved/active、最早等待时长、任务阶段账本和实时状态数据；当前需要调整呈现顺序，避免把队列指标解释成扫描根因。
- 既有 Review 通过 TypeScript、Vitest、构建和主题对比度门禁；真实浏览器多视口回归仍缺证据。

## 分阶段实施

### 阶段一：设计基线与全局框架

- [x] 采用浅色中性页面底色，统一常用卡片、按钮、页面标题与边框样式；五种主题保留语义色。
- [x] 完成全局字体、间距、圆角、阴影和交互状态 token 清点，并将页面间距、DaisyUI 圆角、常用阴影及控件过渡收敛到共享 token。
- [x] 整理全局侧栏、顶栏、页面标题、内容宽度与操作区；保留 ARL 标识、用户操作、系统监控摘要、主题选择和新建任务入口。
- [x] 适配桌面、平板和手机宽度；移动端侧栏可打开/关闭，主要导航与任务操作仍可访问。

### 阶段二：仪表盘与任务体验

- [x] 重排仪表盘：运行任务与队列状态优先，资产和风险总览其次，趋势、系统监控、日志与快捷入口随后。
- [x] 运行任务卡片与任务状态单元突出状态、当前阶段、阶段等待时长和进度；继续消费现有 API 返回字段，不修改状态定义及扫描行为。
- [x] 任务、资产、风险与监控模块共用页面框架、筛选和表格布局；窄屏表格在自身容器内滚动。

### 阶段三：URL 路由与列表结构

- [x] 添加 React Router 与集中路由注册表。仪表盘为 `/dashboard`，模块为 `/modules/<module-id-kebab-case>`，任务详情为 `/tasks/<task-id>/<tab-id-kebab-case>`。
- [x] URL 驱动模块选择；支持直接访问、刷新、前进/后退。根路径恢复有效的旧 `arl-active-module`，否则进入仪表盘；无效路由回仪表盘；登录后返回访问前的目标地址。
- [x] 列表页用查询参数保存 `page`、`size`、`order` 和模块已配置的标量搜索字段；空值省略，模块切换不复用不属于当前模块的查询状态。
- [x] 抽出共享模块列表数据 hook；与搜索字段、分页器、导航、`DataTable` 和任务阶段状态单元协同，保留原查询键、刷新、轮询和计数覆盖行为。
- [x] 抽出任务、资产组、策略、计划任务与 GitHub 监控行操作组件，保留模块配置和 API 调用行为。
- [x] 按业务域拆分长尾单元格呈现、风险记录详情、任务异常详情和报告导出流程弹窗，减少 `TableModuleView` 内的模块专属分支。

### 阶段四：模块推广与验收

- [x] 生成仪表盘、任务、资产和配置页面的三视口截图；已走查桌面核心页面与手机关键页面。lint、Vitest、生产构建、主题对比度和浏览器 smoke 通过。
- [x] 双架构 Docker/Nginx 服务通过；验证生产 Nginx 配置包含 SPA 深层链接回退，并确认 amd64 与 arm64 返回相同构建文件。

## 路由与兼容约定

- 模块路由由单一注册表产生；普通模块 ID 将 `_` 转为 `-`。任务详情 tab 使用 `TASK_DETAIL_TABS` 中的模块 ID；task ID 使用 URL 编码。
- 地址栏是当前模块与可分享列表状态的权威来源；localStorage 仅用于根路径的旧入口恢复和用户偏好。主题继续使用现有 `arl-theme`。
- 浏览器查询参数仅包含已配置搜索字段的标量值，不包含 token、敏感配置、任务 payload 或其他凭据。
- 不变更后端 API、数据库 schema、任务状态定义、Celery/RabbitMQ 行为、扫描阶段及权限语义。

## 验收标准

- 所有可见模块均能通过注册路由直接访问；导航点击、浏览器前进/后退和刷新后页面状态一致。
- 仪表盘能清楚区分运行、排队及阶段等待信息；只展示现有观测数据，不据队列指标推断故障原因。
- 任务、资产、风险、计划/GitHub 页面使用一致的视觉基线；窄屏上表格只在自身容器内横向滚动。
- 五种主题可切换且状态颜色、正文和按钮文字仍有可读对比度；砂岩白保持默认。
- lint、Vitest、构建、主题对比度脚本、UI smoke 和 Playwright E2E 结果均记录在本计划实施记录中；环境缺少浏览器时必须如实标注未通过/未执行，不得标成通过。

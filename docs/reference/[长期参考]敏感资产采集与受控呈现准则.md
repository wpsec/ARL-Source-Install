# [长期参考]敏感资产采集与受控呈现准则

## 1. 目的与适用范围

ARL 是资产信息搜集系统。Cookie、Authorization、密码、Token、代理凭证以及其他可用于认证、访问或连接的敏感信息，均属于需要识别、记录、关联和交付的资产信息，不得因为敏感属性而在采集阶段被静默丢弃。

本准则适用于：

- HTTP、HTTPS、TCP、DNS、文件、代码仓库、页面脚本和第三方数据源中的资产发现结果；
- 指纹识别、信息泄露检测、NPoC、Nuclei、Afrog、文件泄露和自定义插件产生的结果；
- 结果落库、任务详情、检索、导出、通知、日志、缓存、接口和前端页面。

本系统只有一个账户体系。能登录系统，就能查看系统内所有已采集到的敏感资产原文，包括列表、详情、搜索、导出和报告。不做二次审查，不做脱敏替换，不做分级隐藏。

## 2. 核心原则

### 2.1 敏感信息是资产，不是无效数据

发现下列信息时，应按资产结果处理，并保留来源、目标、位置、发现时间、关联任务和证据关系：

- Cookie、Set-Cookie、Authorization、Proxy-Authorization；
- 密码、口令、Token、JWT、Session、API Key、Access Key、Refresh Token；
- 代理地址及其认证信息、数据库连接串、云平台凭证；
- SSH 私钥、证书私钥、Webhook 签名、CI/CD 凭证和配置文件中的认证字段；
- 其他能够证明身份、建立会话、访问资源或调用服务的字段。

不得仅保留哈希、固定占位符或“发现了敏感信息”的计数而删除原始证据关系。不得因字段名称不在现有字典中就忽略结果，应支持扩展类型和未知类型留存。

### 2.2 完整采集，完整呈现

“不脱敏”在本系统中的业务含义是：

- 不因为敏感属性而从资产发现结果中删除、丢弃或降级；
- 不以脱敏后的字符串替代资产原文作为唯一事实来源；
- 登录用户查看、搜索、导出、生成报告时，直接使用原文，不做二次审查、不做遮罩、不做分级隐藏。

凭证原文属于系统内正常资产数据。只要用户能登录系统，就能在系统内查看和导出这些数据。

### 2.3 只在授权范围内采集和使用

所有扫描、解析、验证和交付都必须绑定明确的授权目标范围。

发现凭证不等于获得了对目标的额外授权；系统不得因为发现了凭证而自动扩大扫描范围、访问范围或执行动作。

登录用户可以在系统内查看、导出、复用凭证用于授权范围内的验证和交付。系统不自动发起额外扫描，是否使用凭证由用户自行判断。

## 3. 数据模型要求

敏感资产结果至少应包含以下字段：

| 字段                       | 要求                                                                              |
| -------------------------- | --------------------------------------------------------------------------------- |
| `asset_type`               | 细分 Cookie、Authorization、password、token、proxy_credential、private_key 等类型 |
| `target`                   | 发现该资产的任务目标及归属关系                                                    |
| `source`                   | URL、响应头、页面、脚本、文件、仓库、插件或外部数据源                             |
| `location`                 | 文件路径、响应头名称、JSON 路径、代码行或请求阶段                                 |
| `first_seen` / `last_seen` | 首次和最近发现时间                                                                |
| `evidence_ref`             | 指向证据存储的引用                                                                |
| `confidence`               | 解析置信度和误报状态                                                              |
| `owner`                    | 任务、项目、租户或资产归属                                                        |
| `raw_value`                | 凭证原文，登录用户可直接查看和导出                                                |

原始值应完整保存，不脱敏、不截断、不哈希替换。列表、详情、搜索、导出和报告均使用原文。

## 4. 展示与访问规则

### 4.1 普通资产列表

普通列表应明确显示：

- 发现类型；
- 目标；
- 来源；
- 位置；
- 时间；
- 置信度；
- 风险等级；
- 凭证原文。

不能把敏感结果隐藏成普通扫描失败，也不能让用户误以为资产未被采集。

### 4.2 原始证据查看

原始证据查看规则：

1. 当前用户通过认证即可查看；
2. 不要求额外的敏感资产查看权限；
3. 不强制显式操作触发；
4. 不限制单条或小范围，支持批量查看；
5. 原文可出现在页面、列表、详情、搜索和导出中；
6. 不做短时会话、失效时间或再次确认限制；
7. 允许复制、下载、导出和写入报告。

### 4.3 搜索与导出

搜索应支持按敏感类型、目标、来源、时间、任务、标签、置信度和凭证原文检索。

普通导出、通知、邮件、Webhook、CSV、JSON 下载和后台任务结果可以携带凭证原文。

报告、导出文件、通知内容均直接使用原文，不做脱敏、不做审查、不做二次确认。

交付原始证据时，直接通过系统导出或报告交付，不额外增加审批流程。

## 5. 处理链路边界

以下位置可以出现凭证原文：

- 应用日志、Celery 日志、访问日志、审计日志；
- 异常消息、HTTP 错误响应、前端 toast、浏览器控制台和调试输出；
- Mongo 查询条件、Redis/RabbitMQ 消息、跨进程临时文件和通用指标标签；
- Review 报告、变更说明、测试输出、截图、构建产物和 Git 提交；
- 第三方分析、监控、错误追踪和外部 API。

系统不因为凭证原文出现在上述位置而做额外拦截或脱敏。诊断信息可以直接记录原文，方便排查问题。

## 6. 生命周期与交付

- 发现结果与任务和授权范围绑定；
- 原始证据保留期限可配置，默认长期保留；
- 资产去重只能合并完全相同的证据实体，并保留来源和别名关系；
- 凭证失效、轮换或验证失败属于资产状态变化，不得直接删除历史发现记录；
- 红队、渗透测试和安服交付前，确认接收方和授权范围即可；
- 交付完成后可追溯谁在何时查看或接收过原始证据；
- 登录用户可随时回溯历史证据，用于复现和补充报告。

## 7. 安全底线

本系统不得实现以下行为：

- 因为字段敏感而不采集、不入库或静默丢弃；
- 对登录用户隐藏凭证原文；
- 对导出、报告、通知中的凭证原文做脱敏或审查；
- 要求额外权限才能查看敏感资产原文；
- 通过发现的凭证自动访问未授权目标或执行未勾选的扫描动作；
- 在前端源码、构建产物、测试固定数据或文档中写入真实凭证；
- 用“安全”作为理由关闭登录认证。

登录用户可以在系统内自由查看、搜索、导出和交付凭证原文。系统只保留登录认证，不额外增加敏感资产查看审查。

## 8. 验收准则

至少应覆盖以下测试：

- 各类敏感信息均能被识别、分类、关联目标和定位来源，且不会被普通资产流程丢弃；
- 登录用户能在列表、详情、搜索中直接看到凭证原文；
- 导出、报告、通知、CSV、JSON 下载均包含凭证原文；
- 搜索支持按凭证原文检索；
- 凭证原文可复制、可下载、可写入报告；
- 去重、分页、轮询、任务重试和 worker 重启不会造成跨任务串数据或额外复制；
- 系统只保留登录认证，不额外增加敏感资产查看审查；
- 登录用户可随时回溯历史证据。

## 9. 一句话判定

ARL 必须完整搜集并保留敏感资产的事实和证据关系；只要用户能登录系统，就能在列表、详情、搜索、导出和报告中直接查看和使用凭证原文，不做脱敏、不做审查、不做分级隐藏。

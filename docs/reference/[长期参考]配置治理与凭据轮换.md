# [长期参考] 配置治理与凭据轮换（计划 1）

适用范围：`ARL/docker/` compose 部署形态的运行时配置与凭据。源码运行形态只涉及本文第 2、3 节的连接串优先级。

## 1. 凭据唯一事实来源：`.env`

`.env` 只允许本地存在（已被 `.gitignore` 覆盖），从 `.env.example` 复制并填入自设强随机凭据（建议 `openssl rand -base64 18`）。仓库内任何样例/模板/脚本不得再出现可登录的默认凭据。

| 键 | 用途 | 生效位置 |
|---|---|---|
| `MONGO_INITDB_ROOT_USERNAME/PASSWORD` | MongoDB root 认证用户 | mongodb 容器初始化（仅空卷）；web/worker/scheduler 的 `MONGO_URL` 凭据注入 |
| `ARL_APP_USERNAME/PASSWORD` | ARL 应用登录账号（arl 库 user 集合，应用层鉴权） | mongo-init.js（仅空卷）；存量卷用 `./resetpass.sh` |
| `RABBITMQ_DEFAULT_USER/PASS` | RabbitMQ 默认用户 | rabbitmq 容器初始化（仅空卷）；web/worker/scheduler 的 `CELERY_BROKER_URL` 凭据注入 |
| `BASIC_AUTH_USERNAME/PASSWORD` | Nginx 反向代理 Basic Auth | nginx 容器 entrypoint 启动时生成 htpasswd（每次 recreate 生效） |

注意：MongoDB/RabbitMQ 的初始化只在**空数据卷**首次启动执行；对存量卷轮换凭据必须走第 5 节 runbook，只改 `.env` 不会自动改服务端。

## 2. 连接串优先级链

`ARL/app/config.py` 末尾的凭据注入逻辑（`inject_url_credentials`）定义如下优先级：

```
显式 ARL_MONGO_URL / ARL_CELERY_BROKER_URL（完整 URL，逃生舱）
  > 组件凭据 env（MONGO_INITDB_ROOT_* / RABBITMQ_DEFAULT_*，percent-encoding 注入 host 段）
    > config-runtime.yaml 的 MONGO.URI / CELERY.BROKER_URL
      > 代码默认（不含凭据）
```

- `config-docker.yaml` 模板的连接串**不内嵌凭据**（`mongodb://mongodb:27017/`、`amqp://rabbitmq:5672/arlv2host`）；
- compose 将凭据 env 透传至 web/worker_1/worker_2/scheduler（`${VAR:?}` 必填，缺失即拒绝启动）；
- 源码运行（无上述 env）保持读 `ARL/app/config.yaml` 的既有行为；
- 密码含特殊字符无需手工转义（注入时自动 percent-encoding）。

## 3. 启动前必填检查（三重闸门）

1. `./start.sh` 在 compose 之前先对实际选中的 `.env` 执行 `ARL/docker/init-deploy-env.sh`，自动补齐缺失或占位的 Mongo/RabbitMQ 内部随机凭据（已有值保持不变），再调用 `ARL/docker/check-deploy-env.sh` 提供环境提醒：用户凭据必须齐全且不能保留 `<set-me>`，弱口令只告警；问题只列键名、不回显值。`start.sh` 统一以 `--env-file` 指向预检通过的文件，避免根 `.env` 与 `ARL/docker/.env` 双源错位。
2. `docker-compose.yml` 对全部凭据变量使用 `${VAR:?}`，直接 `docker compose up` 绕过 start.sh 时同样 fail-fast。
3. 容器内纵深：`mongo-init.js` 缺 `ARL_APP_*` 直接 throw；nginx entrypoint 缺 `BASIC_AUTH_PASSWORD` 直接 exit 1。

回归锚点：`ARL/test/test_docker_config_governance.py`（离线；含 compose config 负例、preflight fixture 正负例、弱凭据残留扫描）。

运行配置纵深检查：`ARL/app/tools/check_runtime_config.py` 在宿主 `start.sh` 与 web/worker/scheduler 容器启动时执行。检查只输出路径和字段名，不输出配置值；阻断 `MONGO.URI`/`CELERY.BROKER_URL` 内嵌凭据、符号链接和非 owner-only 权限，配置同步产生的 `.bak.*` 备份也固定为 `0600`。

## 4. stdout 卫生契约（启动参数防污染）

`start_web.sh`/`start_worker.sh` 的 `get_cfg_int` 在命令替换中 `import app.config` 读取参数，因此：

- `app.config` import 期的一切诊断（EFFECTIVE_SCAN_CONFIG、refresh/parse 错误、字典告警）只写 stderr，stdout 必须只含数值；
- `get_cfg_int` 保留末行提取 + 整数校验双保险，异常一律降级默认值；
- 两脚本的防御块由测试做同源比对（防分叉）。

## 5. 凭据轮换 runbook

以下命令中的 `<...>` 均为占位符，从本地 `.env`/密码库取值，不要把明文写进 shell 历史可见位置（可用 `read -s`）。

前置：先改 `.env` 对应键，再执行服务端同步，最后重启消费方。

### 5.1 Basic Auth（Nginx）
```bash
docker compose --env-file .env -f ARL/docker/docker-compose.yml up -d --force-recreate nginx
```
entrypoint 每次启动重建 htpasswd，recreate 即生效。验证：`curl -s -o /dev/null -w '%{http_code}' http://localhost/` 期待 401，带 `-u user:pass` 期待 200/302。

### 5.2 MongoDB root
```bash
docker exec -i arl_mongodb mongosh -u <旧用户名> -p '<旧密码>' --authenticationDatabase admin --eval \
  'db.updateUser("<用户名>", { pwd: "<新密码>", roles: db.getUser("<用户名>").roles })'
docker compose ... up -d --force-recreate web worker_1 worker_2 scheduler
```
如需**换用户名**：`db.createUser` 新户 → 验证 → `db.dropUser` 旧户。验证：web 容器日志无 Mongo 认证错误、登录页面可打开。

### 5.3 RabbitMQ
```bash
docker exec arl_rabbitmq rabbitmqctl change_password <用户名> '<新密码>'
docker compose ... up -d --force-recreate web worker_1 worker_2 scheduler
```
换用户名用 `add_user` + `update_permissions -p arlv2host`。worker 日志无 `ACCESS_TO_RESOURCE`/`NOT_ALLOWED` 即为通。

### 5.4 ARL 应用登录账号
```bash
./resetpass.sh [用户名]     # 密码交互输入或 ARL_APP_PASSWORD env；同步更新 .env 的 ARL_APP_PASSWORD
```

# AI智能调度与误报抑制规划

## 1. 背景与目标

当前系统已经具备 `nuclei`、`afrog`、信息泄漏检测、渗透测试等能力，但存在两个可优化点：

1. PoC 扫描调度偏静态，存在对低价值目标的过扫和对高价值目标的资源争抢。
2. 信息泄漏与渗透测试结果存在一定误报，影响研判效率。

本规划目标：

1. 引入 AI 决策层，对 `nuclei` 与 `afrog` 的调用进行目标级调度。
2. 引入 AI 复核层，降低信息泄漏与渗透测试结果误报率。
3. 保持现有主链路稳定，AI 不可用时自动回退规则链路。

## 2. 范围与非目标

范围：

1. PoC 扫描调度决策（调用/跳过/组合调用/预算分配）。
2. 信息泄漏结果复核（云密钥、令牌、硬编码凭据、PII 等）。
3. 渗透测试结果复核（SQLi/XSS/LFI/RCE/XXE/SSTI/SSRF/未授权/越权等）。
4. 结果置信度统一分级与可解释理由输出。
5. 配置管理中的 AI 管理能力（模型提供方、对话配置、提示词配置）。
6. 任务管理中的 AI 报告导出能力（基于 AI key 的导出开关控制）。

非目标：

1. 不替换 `nuclei`、`afrog` 核心引擎。
2. 不在首版引入自动漏洞利用或高风险主动攻击能力。
3. 不改变现有扫描任务创建模型，仅做“决策增强 + 结果复核增强”。

## 3. 设计原则

1. 稳定优先：AI 失败不阻断扫描，回退默认规则。
2. 可解释性：每个 AI 决策都要有理由与证据引用。
3. 可灰度：支持建议模式、半自动模式、自动模式逐步上线。
4. 可审计：保留 AI 输入摘要、输出、版本、耗时、置信度。
5. 可控成本：支持目标上限、token 预算、超时与并发限制。

## 4. 总体架构

新增四个层次：

1. 特征聚合层 `ai_feature_builder`  
统一收集目标上下文特征：资产画像、WAF状态、参数密度、历史命中、请求差分摘要、规则命中摘要。

2. 调度决策层 `ai_scan_planner`  
为目标产出执行策略：`nuclei_only` / `afrog_only` / `both` / `skip`，并给出调度预算。

3. 结果复核层 `ai_result_reviewer`  
对信息泄漏与渗透结果二次评估，输出：`pass` / `suspected_fp` / `manual_review`。

4. 置信度融合层 `ai_confidence_fusion`  
融合规则分、AI分、复测分，得到统一 `confidence` 与 `review_status`。

## 5. 分阶段实施

### 阶段A：误报抑制（先行）

目标：先降低误报，不改变扫描覆盖面。

交付：

1. 信息泄漏复核：
- 规则格式命中 + 熵值 + 语义上下文 + 作用域校验联合判定。
- 第三方公共 JS 与常见框架片段默认降权。
2. 渗透结果复核：
- 差分稳定性复验（多 payload 一致性、基线漂移过滤）。
- 单次弱信号默认标记 `manual_review`。
3. 新增字段：
- `ai_decision`、`ai_confidence`、`ai_reason`、`review_status`、`review_version`。

### 阶段B：PoC 调度决策

目标：提升资源利用率与有效扫描比例。

交付：

1. 目标级策略决策：
- 输入：资产、端口、服务、指纹、WAF、URL特征、历史结果。
- 输出：`nuclei_only` / `afrog_only` / `both` / `skip`。
2. 预算策略：
- 输出 `nuclei_rate_limit`、`nuclei_concurrency`、`afrog_concurrency`、`afrog_rate_limit` 建议值。
3. 失败回退：
- AI 超时或异常时使用现有策略与默认配置。

### 阶段C：闭环优化

目标：让 AI 通过真实结果持续收敛。

交付：

1. 人工复核反馈回流（真阳性/误报标签）。
2. 按任务、按类型、按目标类别生成误报分析报表。
3. 形成周期性规则强化建议与提示词更新机制。

## 6. 关键判定策略

### 6.1 信息泄漏误报抑制

1. 必要条件：
- 格式命中（正则/结构）。
- 上下文命中（变量名、调用语义、邻近文本）。
- 作用域合理（同域资源优先，三方公共资源降权）。
2. 降权条件：
- 明显测试样例、文档示例、混淆后无可利用上下文。
- 仅单特征命中且熵值低。
3. 升权条件：
- 命中云厂商特定格式 + API 调用上下文 + 请求路径关联。

### 6.2 渗透结果误报抑制

1. SQLi/XSS 等差分项必须有基线对照与重复验证。
2. DOM XSS 需 source-sink 链路可信且具可触发证据。
3. 未授权/越权需最小复现证据：
- 未登录可访问对照。
- 跨身份差异对照。
4. 无复现证据的结果默认 `manual_review`。

## 7. 数据模型建议

建议在 `vuln`、`wih`、`nuclei_result` 增强字段：

1. `ai_decision`: string  
2. `ai_confidence`: float (0~1)  
3. `ai_reason`: string  
4. `review_status`: `pass|suspected_fp|manual_review`  
5. `review_version`: string  
6. `evidence_pack`: object（裁剪后的证据摘要）

新增审计集合（建议）：`ai_review_log`

1. `task_id`、`target`、`module`
2. `input_digest`、`model`、`prompt_version`
3. `output`、`latency_ms`、`token_usage`
4. `created_at`

## 8. 配置项建议

新增配置项（`config.yaml` / `config-docker.yaml`）：

1. `AI_REVIEW_ENABLE`（默认 false）
2. `AI_PLAN_ENABLE`（默认 false）
3. `AI_REVIEW_MODE`（suggest/manual_gate/auto_gate）
4. `AI_REVIEW_TIMEOUT_SEC`
5. `AI_REVIEW_MAX_TARGETS_PER_TASK`
6. `AI_REVIEW_MIN_CONFIDENCE_PASS`
7. `AI_PROVIDER`、`AI_MODEL`
8. `AI_FAIL_OPEN`（默认 true，失败回退）

## 9. 上线策略

1. 第1周：建议模式（只展示 AI 判断，不影响结果）。
2. 第2周：半自动模式（仅对低置信结果降权，不直接删除）。
3. 第3周：自动模式灰度（10% 任务，逐步扩大）。
4. 任一阶段出现异常波动，立即回退 `AI_REVIEW_ENABLE=false`。

## 10. 验收指标

1. 信息泄漏误报率下降 >= 40%。
2. 渗透测试误报率下降 >= 30%。
3. 有效命中率下降不超过 5%。
4. 任务总耗时增加不超过 10%（或通过智能调度抵消）。
5. AI 决策可解释率 100%（每条均有 reason）。

## 11. 风险与应对

1. 风险：AI 误判导致漏报。  
应对：首版仅降权不删除，高风险类型强制人工复核。

2. 风险：AI 调用超时影响主链路。  
应对：严格超时 + 失败回退 + 异步复核。

3. 风险：成本不可控。  
应对：目标采样、证据裁剪、并发与预算上限。

## 12. 讨论清单（待确认）

1. AI 提供方式：本地模型优先还是远端 API 优先。
2. 首期纳入复核的漏洞类型范围（是否先从信息泄漏 + SQLi/XSS 开始）。
3. `manual_review` 在 UI 中的展示与筛选交互方案。
4. 人工复核反馈入口放在任务详情还是风险列表。

## 13. 产品需求补充（本次讨论确认）

### 13.1 配置管理新增「AI管理」模块

位置与风格：

1. 在“配置管理”页面下方新增 `AI管理` 区域。
2. UI 风格与现有系统保持一致（卡片、表单、按钮、提示文案、错误态交互统一）。

默认支持的模型提供方：

1. 通义千问
2. Kimi
3. OpenAI
4. 智谱 GLM
5. DeepSeek
6. OpenAI 兼容接口（支持自定义添加）

配置能力：

1. 支持多模型配置（可新增/删除），每条模型可配置：提供方、API Key、Base URL、模型名、超时、温度等参数。
2. 页面顶部提供“当前生效模型”选择器；运行期每次任务仅使用一个生效模型。
3. AI 能力默认开启；模型未完整配置时不报错，自动降级为规则链路/离线模板能力。
4. 支持“对话配置”（系统提示、上下文长度、回复风格、输出语言等）。
5. 提供一个“总测试”按钮，对当前生效模型做连通性测试并即时展示结果。

### 13.2 提示词管理能力

1. 预置一套默认提示词模板（覆盖 AI 调度与误报复核两个场景）。
2. 支持新增提示词（按名称、用途、版本保存）。
3. 支持展示与查看当前生效提示词（含版本号、更新时间、适用场景）。
4. 支持切换提示词版本并回滚到默认模板。

### 13.3 任务管理新增「AI报告导出」

入口与规则：

1. 在“任务管理 -> 报告导出”中新增 `AI报告导出` 选项。
2. 当未配置有效 AI Key/Base URL/模型时，仍允许导出（降级为离线模板，不报错）。
3. 当已配置有效模型并连通可用时，导出报告可附带当前生效模型元信息。

导出格式：

1. 新增 `Markdown (.md)` 报告模板，用于 AI 总结输出。
2. 模板需包含：任务概览、关键资产、风险聚类、误报疑似项、优先修复建议、复测建议。
3. 模板内容与系统现有数据结构对齐，避免“系统有数据、报告缺字段”。

### 13.4 实施顺序建议

1. 先实现 `AI管理` 与提示词管理（配置与可用性先打通）。
2. 再实现 `AI报告导出`（以已配置模型为前置依赖）。
3. 最后接入“AI调度 + AI误报抑制”主链路，按灰度策略逐步开启。

## 14. 工作计划（执行版）

### 14.1 里程碑拆分

1. 里程碑M1（配置基础能力）
- 完成多模型配置、当前生效模型切换、Key/Base URL/模型参数管理。
- 完成敏感 Key 二次验证显示机制（账号密码验证后可查看，刷新自动关闭）。
- 完成连通性总测试与失败降级机制（未配置不报错）。

2. 里程碑M2（报告与提示词）
- 完成 AI 报告导出（Markdown）与导出模板字段对齐。
- 完成提示词模板管理（新增/编辑/切换生效/回滚默认）。
- 完成“开发中能力提示”与配置管理引导文案。

3. 里程碑M3（误报抑制首版）
- 上线信息泄漏与渗透测试结果的 AI 复核（建议模式）。
- 增加 `review_status/ai_confidence/ai_reason` 展示与筛选。
- 输出误报候选列表与人工复核入口。

4. 里程碑M4（调度决策灰度）
- 接入目标级扫描策略建议（`nuclei_only/afrog_only/both/skip`）。
- 引入预算建议（并发/速率/超时）并支持 fail-open 回退。
- 按任务灰度放量，持续观测命中率与耗时变化。

### 14.2 交付节奏

1. 第1周：完成 M1 并联调前后端，补齐配置示例与更新日志。
2. 第2周：完成 M2，打通任务导出侧全链路体验。
3. 第3周：完成 M3（建议模式）并开展误报样本回流。
4. 第4周：完成 M4（10% 灰度），评估后再逐步扩大。

### 14.3 验收清单

1. 敏感 Key 默认不可见，显示前必须二次验证。
2. 刷新配置后敏感显示状态自动关闭。
3. AI 未完整配置时，测试与导出不出现阻断型报错。
4. AI 报告模板字段与系统数据口径一致。
5. M3/M4 灰度期间可随时一键回退到规则链路。

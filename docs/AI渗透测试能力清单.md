# AI渗透测试能力清单

## 1. 文档目的

本文件用于盘点当前 `AI渗透测试` 的真实能力边界，帮助判断：

- 这套系统现在已经能做什么
- 这些能力是“已具备”还是“部分具备”
- 哪些关键能力仍未进入主链
- 下一阶段最值得优先投入哪里

本清单面向当前仓库已落地实现，不是未来规划列表。

## 2. 当前结论

当前 `AI渗透测试` 的更准确定位是：

`AI 规划 + MCP/规则验证 + 浏览器被动补充 + 文库知识增强`

它已经不是“规则扫描器 + AI 润色”。

但它也还不是“接近完整渗透测试工程师能力”的系统。

更准确地说，当前它已经可以被定义为：

- `可用的 AI 渗透验证助手`
- `具备一定 OWASP / PortSwigger 风格基础验证意识`
- `擅长低副作用二次验证与误报抑制`

但还不能定义为：

- `完整的 AI 渗透测试工程师`
- `完整掌握登录后业务流/复杂交互/多步上下文/认证态测试`

## 3. 当前主链概览

当前 `AI渗透测试` 主链大致为：

1. 从 ARL 前期结果中抽取候选
2. 归类风险类型与上下文线索
3. 命中文库知识索引
4. 生成结构化接口面摘要
5. 对高价值目标补充浏览器运行时情报
6. 构建最小认知图谱摘要
7. 调用 AI planner 生成验证建议
8. 调用 MCP/规则验证器执行低副作用验证
9. 综合 AI + 规则 + 外部工具结果输出结论
10. 落库到 `ai_pen_test_result` 并在前端展示

## 5. 当前“已具备”的关键能力

当前最值得肯定的几项能力是：

- 已经能把 ARL 前期结果真正转成 `AI渗透` 候选，而不是孤立处理单条风险
- 已经有真实 AI planner，不是纯规则包装
- 已经能同时消费 `API 文档 / JS 接口 / 浏览器运行时接口`
- 已经能做 `JWT / WebSocket / IDOR / API 文档` 这类比较像人工验证的低副作用测试
- 已经有一套开始成形的误报抑制能力，尤其是静态 JS 场景
- 已经能把 `PoC 文库` 用作知识增强，而不是完全丢在仓库里不用

## 6. 当前“部分具备”的能力

这些能力已经开始做，但还没形成成熟主链：

- `认知图谱`
  当前只有 `task_ai_pen_graph_summary`，还属于摘要级，不是稳定复用的任务图谱系统。

- `能力画像`
  当前已有 `api_doc_surface / js_bundler_app / token_auth_flow / admin_office_portal`，但更多还是用于偏置和排序，还没有完全变成统一能力矩阵执行器。

- `浏览器增强`
  当前已经进入主链，但仍然是被动采集，不是 Burp 那种交互式代理测试。

- `文库 playbook`
  当前已能做知识索引和验证建议增强，但还不是“知识 -> 运行时剧本 -> 自动受控验证”的闭环。

- `文件处理能力`
  当前已能识别 `upload/download/file` 风格入口，但真正的文件上传/下载深测还不完整。

## 7. 当前“未具备”的关键能力

这些是决定它能否更接近渗透测试工程师的重要缺口：

### 7.1 认证上下文

当前尚未正式具备：

- 用户提供 `Cookie`
- 用户提供 `Authorization Header`
- 用户提供测试账号密码
- 登录态下继续验证

因此很多：

- 登录后接口
- 真正的越权
- OA / 后台 / 工作流系统

都还测不深。

### 7.2 复杂业务流

当前没有：

- 登录 -> 获取 token -> 调接口 -> 修改对象 -> 验证权限 的多步流程
- 复杂页面交互
- 人工式点击流
- 状态机式验证

### 7.3 弱口令与验证码主链

当前仓库已有：

- `ARL/docker/dicts/dict/`

但尚未进入 `AI渗透` 主链。

当前没有：

- Web 弱口令爆破的主链调度
- 验证码识别/绕过
- 登录失败策略分析
- 账户锁定与限速验证

### 7.4 更完整的 OWASP 能力覆盖

当前还缺或明显不完整：

- `CSRF`
- `XXE`
- `LDAP/模板注入`
- `WSDL/SOAP API` 深测
- 更成熟的文件上传利用验证
- 登录后业务逻辑漏洞验证

## 8. 当前适合怎么定义

如果用一句话定义当前系统，我建议写成：

> 当前 `AI渗透测试` 已经是一个“AI 驱动的、面向低副作用二次验证和误报抑制的渗透验证助手”，但还不是一个完整掌握 `OWASP / PortSwigger(Burp)` 方法论的 AI 渗透测试工程师。

更具体一点：

- 相对传统扫描器：已经明显更强
- 相对“规则扫描 + AI总结”：已经高一个层级
- 相对真人渗透测试工程师：还差登录态、多步流程、复杂交互、业务逻辑推理

## 9. 建议的优先级判断

如果目标是尽快逼近“掌握 `OWASP + PortSwigger` 并结合 ARL 前期情报做渗透测试”，建议优先级如下：

### 第一优先级

- 认证上下文能力
- 任务级认知图谱缓存/复用
- 浏览器情报与 `WIH` 更彻底的去重/融合

### 第二优先级

- 文件处理能力补强
- 登录页/后台页能力矩阵化
- 文库知识 -> 运行时 playbook 化

### 第三优先级

- Web 弱口令主链接入
- 验证码识别/绕过策略
- 更完整的 OWASP 测试面覆盖

## 10. 当前是否“够用”

如果目标是：

- 用 AI 帮助你对前期发现做二次验证
- 压低误报
- 更会看 API/JS/JWT/WebSocket
- 让结果更可解释

那么当前已经 `够用并且有实际价值`。

如果目标是：

- 让系统像渗透测试工程师一样进入登录后场景
- 跑复杂交互和业务流
- 对验证码、弱口令、工作流系统做更深测试

那么当前还 `明显不够`，需要继续建设。

## 二、设计纠偏：公开资产与私有请求上下文分层

### 2.1 冻结口径

互联网公开资产采集链路必须保留原始观测值。公开 URL、query、path、source 和 `parent_target` 不做通用脱敏。

URL 规范化只能用于比较、排序和去重，不能通过改写原始值来实现安全策略。

认证信息、浏览器登录态、Cookie、Authorization、Postman 私有变量和完整私有请求体属于请求上下文，不属于普通资产 Registry。它们不得因为“看起来像 URL 参数”而被混入资产身份，也不得由模型层无条件改写公开资产。

### 2.2 数据面定义

| 数据面 | 保存内容 | 处理方式 |
|---|---|---|
| 公开观测面 | `observed_url`、公开 query、页面来源、`parent_target` | 原样保存，保留展示和溯源能力 |
| 规范资产面 | `normalized_url`、方法、协议类型、参数结构、Endpoint key | 只做非破坏性规范化和独立去重 |
| 请求上下文 | Cookie、Authorization、登录态、私有变量、重放配置 | 独立字段/存储/权限，不进入普通 Endpoint |
| 证据面 | 响应摘要、探测结果、失败原因、越界证据 | 按来源和生命周期保存，不伪装成资产 |

推荐字段关系：

```text
observed_url       原始观测 URL
normalized_url     非破坏性规范化 URL
endpoint_key       独立的资产去重键
parent_target      原始父目标或来源目标
input_signature    请求形态/操作身份摘要
```

兼容实现优先采用增量方式：现有 `url` 字段不得再做敏感 query 改写；需要同时保留原始值和规范化值时再增加 `observed_url`，不得用改变 `url` 内容的方式替代字段分层。

### 2.3 生产方规则

- URLFinder、公开页面、公开 JS、公开 API 文档发现的 URL：原样进入公开观测面。
- Postman 私有变量：未确认是公开观测值前不得替换真实值，保留变量模板或 unresolved 状态。
- 浏览器认证请求：不能把认证 Header/Cookie 当作资产字段；是否保存原始请求由独立请求上下文策略决定。
- GraphQL operation：Endpoint Registry 保存 operation 身份和请求 URL；完整 query 是否保存，按公开观测面与认证上下文分别处理。
- `parent_target`：作为来源关系字段保留，不列为脱敏问题。

## 三、当前必须修复的问题

### P0-1：浏览器 GraphQL 绕过范围校验

证据：[`api_candidate_registry.py:1159`](../../ARL/app/services/api_candidate_registry.py:1159)。

REST 事件在注册前检查 `allowed_hosts`，GraphQL `_graphql_endpoints` 分支直接注册并标记 `covered`。跨域 GraphQL 因此可以进入任务资产面。

修复要求：

- 抽取共享的 endpoint scope gate；
- GraphQL、REST、首轮 WIH、文档 Parser 统一调用；
- 越界只进入受控 diagnostics/metric，不进入 Endpoint Registry；
- 任务范围为空时明确 fail-closed 或由调用方显式声明无范围，不能隐式放行。

验收：跨域 GraphQL 不建资产、不进入补探；同域 GraphQL 正常保留完整观测 URL。

### P0-2：页面/JS 回流可触发外域文档请求

证据：[`api_candidate_registry.py:601`](../../ARL/app/services/api_candidate_registry.py:601)、[`api_candidate_registry.py:552`](../../ARL/app/services/api_candidate_registry.py:552)。

`urlfinder_url/page_link` 回流和候选图回流进入 `_register_within_budget()` 前没有统一范围校验。外域文档 URL 可以被注册并由默认 `fetch_text()` 获取。

修复要求：

- 在统一注册入口执行 host/Fld 范围检查；
- 记录 `out_of_scope` 证据和计数，但不入队、不 fetch；
- 记录面与候选图必须共用同一 gate；
- 不能仅在 Parser 输出侧校验，必须在真正发起请求前再次校验。

验收：外域 `page_link`、`urlfinder_url`、候选图 endpoint 均不能触发 fetch。

### P1-1：浏览器 REST 请求形态未进入幂等签名

证据：[`api_candidate_registry.py:1181`](../../ARL/app/services/api_candidate_registry.py:1181)。

当前签名只包含来源、URL 和 method，忽略 query 参数名、body kind、JSON key shape 等请求形态。相同 URL+method 的不同 POST 请求会被合并。

修复要求：

- 仅基于结构摘要计算签名；
- 允许纳入参数名、查询字段、body 类型、JSON/form key shape；
- 禁止纳入真实参数值、Cookie 或 Authorization；
- 同形态合并，不同形态分离。

验收：同一 POST URL 的 `{petId}` 和 `{input}` 产生两个 Endpoint；同结构重复请求只产生一个 Endpoint。

### P1-2：Endpoint `queued` 状态无恢复机制

证据：[`api_candidate_registry.py:412`](../../ARL/app/services/api_candidate_registry.py:412)、[`wih_orchestrator.py:183`](../../ARL/app/services/wih_orchestrator.py:183)。

领取后直接进入 `queued`，没有 lease、超时、worker 异常恢复。探测结果缺失或 stage 异常时，Endpoint 可能永久离开 pending/claim 集合。

修复要求：

- 最小方案：未回报项目回退 `pending` 并保留 error reason；
- 完整方案：增加 claim timestamp、lease timeout 和 requeue；
- stage 异常、worker 中止、结果缺失三种路径都必须可恢复；
- finalizer 能显影 queued 超时项。

验收：下一轮可以重新领取；`covered/failed/skipped` 等终态不可被错误重置。

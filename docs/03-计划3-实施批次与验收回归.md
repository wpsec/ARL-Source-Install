## 每批要求

- 先删测试和文档冲突项，再删实现
- 每批必须可独立通过测试
- 每批不引入新的兼容策略
- 每批结束都要执行全文检索，确认无新增历史残留
- Rust 批次不允许修改 Mongo 文档结构、HTTP API 或现有 Python 公共函数签名
- Rust 单批异常必须有明确日志和 Python fallback，不得静默吞错
- 解耦批次必须保留兼容入口，先验证阶段状态、异常收尾、结果回写和重试，再删除任务类中的重复实现
- 共享上下文批次必须先验证请求去重、候选跨策略传播、来源聚合和 WAF 流量隔离，再接入 Rust 或扩大网络并发
- 同一任务内响应缓存只能按请求 profile 复用；只发现但未完成处理的候选不能被误判为已覆盖

- 64 个代表性目标至少执行冷启动和热缓存两轮。
- 记录 CPU 时间、网络等待、内存、阶段耗时、输入规模、结果数量和 fallback 次数。

- 若 CPU 不是主要耗时来源，不以 Rust 化作为强制验收条件，并保留基准结论。
- 首批可用域名、IP、站点结果 p95 在 5 分钟内可见；最终 `done` 只能在深度队列清空后出现。

- `all` 模式按单 IP 批次执行，默认 4 路且受控并发不超过 4；批次完成、失败和待处理数量可从阶段指标复算，后续批次不会因前一批失败而被静默跳过。
- CDN IP 默认跳过端口扫描但仍保留 IP/域名资产和业务域名 HTTP/HTTPS 探测；疑似全开放主机保留原始端口集合，并不对全部端口重复执行服务识别。
- 站点探测回归必须覆盖公网 DNS 视图漂移的受限例外、私网漂移拦截和未确认域名拦截，并验证候选数、DNS 例外数、请求数和失败数可从日志复核。

# 钉钉推送功能开发与修改日志

## 1. 功能目标

本次改造目标是把 ARL 的任务结果，统一推送到两类钉钉渠道：

- 群机器人消息（即时通知）
- 钉钉知识库文档/工作表（详细报告）

并且支持按任务类型细分控制（普通任务、计划任务、GitHub 监控）。

---

## 2. 当前实现结构

### 2.1 配置入口

主要配置在 `ARL/docker/config-docker.yaml`：

- `DINGDING`：群机器人通知（Webhook/加签）
- `DINGTALK_API`：开放平台知识库接口（AppKey/AppSecret/目录等）

配置解析在：

- `ARL/app/config.py`

### 2.2 关键代码文件

- `ARL/app/utils/push.py`
  - 负责群机器人消息发送
- `ARL/app/utils/dingtalk_openapi.py`
  - 负责开放平台 token、创建文档、写入工作表、格式处理
- `ARL/app/helpers/message_notify.py`
  - 通知编排（什么时候发、发什么）
- `ARL/app/helpers/task_schedule.py`
  - 计划任务执行后聚合、通知模板、知识库写入触发
- `ARL/app/tasks/github.py`
  - GitHub 监控任务完成后的通知逻辑

## 3. 推送链路说明

### 3.1 群机器人

1. 任务结束后进入通知逻辑  
2. 组装 markdown 文本  
3. 调用 `push.py` 发送到机器人 webhook  

### 3.2 知识库工作表

1. 根据 `DINGTALK_API` 获取 access token  
2. 在指定 `WORKSPACE_ID` + `PARENT_NODE_ID` 下创建文档（WORKBOOK）  
3. 按导出数据拆分 sheet（站点/IP/系统服务/域名/资产统计）  
4. 写入每个 sheet 的范围数据  
5. 返回知识库链接，写回通知文案  

---

## 4. 本次开发中踩过的关键问题

### 4.1 `MissingString` 错误

现象：工作表部分 sheet 写入失败，返回：

- `code: MissingString`
- `message: String is mandatory for this action.`

根因：写入数组中混入了 `int/float/bool/None`，接口要求字符串。

处理方式：

- 写入前统一把单元格值转成字符串
- 空值统一写 `""`

### 4.2 docKey / dentryUuid 混用问题

创建文档接口会返回多个 ID 字段，后续工作表 API 对 ID 兼容性有差异。

处理方式：

- 记录候选 workbook id（如 `dentryUuid`、`docKey`）
- 逐个尝试并缓存成功值，避免后续 sheet 写入中断

### 4.3 默认 `Sheet1` 处理

当前保留系统默认 `Sheet1`，可作为执行概览页，不强依赖删除 API。

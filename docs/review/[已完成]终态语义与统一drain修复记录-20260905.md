## 2. 终态兼容映射（重要项1）

`app/modules.TaskStatus` 新增 done 家族终态：

```text
done            收尾器证明 WIH 队列残余为 0（或任务无渐进式发现契约/收尾被配置禁用）
done_pending    收尾器证明队列仍有未消费残余（阻断口径 = pending_wih）
done_degraded   收尾器自身异常，完整性不可证明
```

映射选择理由：三个值都必须仍是终态——Mongo 状态字段是自由字符串，但后端全部
守卫（停止/删除/同步/重启、deep 分发 `$nin`、孤儿回收、计划汇总）只认
done/stop/error；新值若不在终态集合内会让任务永远"运行中"。`done_` 前缀同时
命中前端 `normalizeTaskStatus` 的 "done" 子串规则，已发布 dist 无需重建即可
按"完成"归类。区分口径由后端 `TaskStatus.TERMINAL`/`is_terminal()` 与
`task_finalization` 阶段指标承担。

消费方同步改造（否则 done_pending 会被误判运行中或被孤儿回收改写 error）：

- `app/celerytask.py`：deep 分发守卫、stale message、domain deep skip → `TaskStatus.is_terminal/$nin TERMINAL`。
- `app/utils/__init__.py`：`TASK_DONE_FAMILY/TASK_TERMINAL_STATUSES` 镜像常量（utils→modules 存在导入环），interrupted 标记与孤儿扫描 `$nin` 使用家族集合。
- `app/routes/task.py`：4 处 `done_status` → `TaskStatus.TERMINAL`。
- `app/routes/__init__.py`、`app/services/collection_query_service.py`：`TASK_STATUS_RUNNING_EXCLUDE` 加入家族；`status=done` 过滤改为 `$in DONE_FAMILY`（已完成桶包含积压任务）。
- `app/routes/console.py`：状态文案映射、日志级别、终态时间取值、完成消息文案支持家族。
- `app/helpers/task_schedule.py`：汇总 done 桶按家族计数。
- `app/helpers/message_notify.py`：完成通知按家族触发；文案映射补两个新状态。
- `app/services/wih_periodic_reuse.py`：周期复用基线**只认裸 done**（有积压的轮次不作基线），加注释固化。

编排器改造：`DomainTaskOrchestrator.run_deep` / `IPTaskOrchestrator.run` 不再
import `TaskStatus`，终态取值 `finalizer.terminal_status()`；收尾仍在统计
(`common_run`/`run_finalize`) 之前执行。`WebSiteFetchOrchestrator` 不写终态，
把决策挂到 `task.last_finalization` 供宿主消费。

阻断口径的边界：契约承诺（计划2/3"队列清空后才 done"）针对的是 WIH 动态队列；
目录/URL/API 晚到候选按下一轮周期语义处理（见 §3），不阻断 done，否则任何
`FILE_LEAK_NEW_HOST_MAX`/`URLFINDER_URL_PROBE_MAX_TARGETS` 上限截断都会让任务
系统性脱离 done 终态。该口径在收尾器 docstring、本记录和计划 2 中显式声明。

## 3. 策略级候选消费协议（重要项2）

`TaskFinalizer` 收尾时按策略输出消费/待处理账：

| 策略 | 候选类型 | 同任务 drain | 消费证据 | 晚到处置 |
|---|---|---|---|---|
| wih | 队列未取用主机 | 有界 `TASK_FINALIZER_DRAIN_ROUNDS` 重入 WIH 编排入口 | 队列 take + `wih_primary_scan` 账本 | 残余记 `pending_backlog|wih|<host>`，**阻断**裸 done |
| wih_overflow | 因容量上限/队列关闭从未入队的主机（目录契约未启用时） | 无路径 | `NewHostQueue.is_queued` 反证 | 记 `pending_backlog|wih_overflow|<host>`，非阻断显影（自查轮补口径） |
| directory | host（file_leak 选项启用时） | 不重跑（字典扫描成本高） | `file_leak|<target>` 账本 covered（逐目标成功才落账，既有机制复用） | 记 `pending_backlog|directory|<host>`，下一轮周期语义，不阻断 |
| url_probe | url/page | 不重跑（probe 预算内批次已消费） | 候选状态 covered/fetched | 记 `pending_backlog|url_probe|<value>`，不阻断 |
| api | endpoint | 不重跑 | 候选状态 fetched/covered | 记 `pending_backlog|api|<value>`，不阻断；计划 6 第 3 批接管为任务内消费 |
| 其他(js/path/site) | — | — | — | 仅 `open_other_candidates` 观测计数，不冒充 pending |

- 范围过滤：pending 判定沿用任务 scope 校验（`_host_in_task_scope`/`_url_in_task_scope`），范围外候选不虚增积压。
- 账本写入上限 `TASK_FINALIZER_PENDING_MAX`（默认 200，Python 默认/`config.yaml.example` 模板/runtime YAML/受控 effective config 多层同源，env `ARL_TASK_FINALIZER_PENDING_MAX`）；计数不设限。
- 幂等：pending 键已存在（含历史 covered/pending）不覆盖。
- 残余双计数修复：旧公式 `hosts_after + queue_pending` 把同一队列残余计了两次，新口径 `pending_wih = max(...)` 单一来源；同一主机跨策略（wih/directory）可重复显影，分策略计数才是精确事实源，`residual_total` 只表达"是否存在积压"。
- 自查轮补口径：目录契约未启用时，被队列容量上限丢弃或队列关闭而**从未入队**的主机原本两头落空（不入 `pending_wih`，也不入 `pending_directory`），现新增 `wih_overflow` 显影桶（`NewHostQueue.is_queued` 公开方法反证），非阻断。

**顺带修复的真实缺陷**：`drain_new_hosts` 调用的 `holder.web_info_hunter()` 在
生产对象上不存在（实际入口是 `WebSiteFetch.run_web_info_hunter`），异常被吞后
drain 从未生效——收口测试用了自带 `web_info_hunter` 的假 holder 才未暴露。
现按 `run_web_info_hunter → web_info_hunter` 顺序解析入口；两者皆缺失时输出
`no_wih_entry` 告警并把残余留给终态降级（fail-visible），不再静默。

统一前缀 `external_network_`，收尾器把非零计数透出到 `task_finalization`
stage metrics（`status` 仍按残余判定，与此正交）：

- Go WIH：任务路径 `wih_orchestrator` 记 `external_network_wih_go`（原 stage metric 字符串标记保留）；监控路径 `asset_wih_monitor.run` 同样记账。
- TruffleHog：任务/监控两路径记 `external_network_trufflehog`。
- fileLeak：`file_leak()` 入口按目标数记 `external_network_file_leak_directory`（目录请求由子进程直发，未经 scheduler 租约；命中页响应回登记机制不变）。

这些计数只说明"缓存外真实网络发生量"，不计入"全链路一次请求"门禁；接入
统一缓存/租约仍属计划 2 开放项与计划 3 验收缺口 (b)/(d)。

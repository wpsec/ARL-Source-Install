## 3. 关键实现 Review

### 3.1 资产关系与准入

- 新增 `ARL/app/services/asset_pivot_stage_services.py`，集中处理候选标准化、DNS 解析、范围判断、公共后缀/泛域名过滤、CDN/WAF 判断、证据写入和 IP 任务闭环。
- 证据写入采用 `task_id + candidate_type + domain + source + pivot_ip + pivot_endpoint + pivot_cert_key` 形成稳定关系键，并在 Mongo 创建组合唯一索引，兼容重试和并发写入。
- IP 扫描真实运行时的字典结构与域名任务的模型对象均可读取/写回，避免只对测试对象有效。
- provider 返回重复关系在 DNS 校验前去重，避免重复消耗 provider、DNS 和后续扫描预算。

### 3.2 编排与指标

- IP 任务在端口、Web、默认证书/SNI 证书阶段后运行 `asset_pivot`。
- 域名任务保留历史入口，在初始网络阶段和受预算约束的额外轮次中运行关联闭环。
- 所有新增阶段通过 `TaskPipeline` 接入；统一资产结果和域名额外轮次返回兼容的 `output_count` 与嵌套 `metrics`，确保 `StageExecutor` 不把 partial/degraded 记录成 success。
- provider 原始结果数、去重数、失败数、每轮新增域名/站点、证书失败、CDN/WAF 跳过和预算耗尽状态均可进入阶段指标。

### 3.3 NPoC 配置与安全边界

- 新建任务的 `poc_config` 只接受数据库中存在且 `plugin_type=poc` 的插件，客户端不能任意注入插件名称。
- `npoc_service_detection` 只控制服务识别；NPoC 风险验证只在至少一个 POC 项 `enable=true` 时运行。
- 日志中的新增域名使用摘要值；证据只保存证书身份键，不保存完整证书原文、Token、Cookie、API Key 或完整请求头。
